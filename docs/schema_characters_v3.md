# OpenBook Character Schema v3.0

> **Status:** Character storage is now **v3.0** — one file per alias cluster in `Book-N/characters/`, GUID identity.
> - The v2-era centralized `characters.json` format is documented for reference/migration history in [schema_v2.md](./schema_v2.md) (its character sections are **no longer a write target**).
> - Dialogue format is unaffected: see [schema_v3.md](./schema_v3.md). **Note:** "v3.x" in `schema_v3.md` is the *dialogue.json* version line; the character-files v3.0 here is a separate, independent line.

**Date:** 2026-10-06
**Supersedes:** `characters.json` v2.0 as the character source of truth (owner rulings R2–R4).

## Overview

Each alias cluster (character) is one JSON file in a `characters/` folder at the book root. The file is **named by the character's title**. Identity is a **short GUID**, fully decoupled from titles, names, and aliases. Every cross-file reference to a character carries the GUID.

Core safety property: **a title rename touches exactly one file** (the character file itself, renamed). No reference in `dialogue.json`, rosters, `voices.json`, or manifests ever changes on a rename.

## Folder layout

```
Book-N/
├── characters/                      # v3.0 source of truth
│   ├── Catherine.json               # filename = sanitized current title
│   ├── Cat-and-Mouse.json
│   └── 7KQX2MFT.json                # fallback name (case-collision case, below)
├── characters.json                  # RETIRED — deleted by migration; must not be rewritten
└── <Chapter>/
    ├── <Ch>.characters.json         # roster: GUID refs
    └── dialogue.json                # lines reference GUIDs
```

## File format (v3.0)

```json
{
  "formatVersion": "3.0",
  "guid": "7KQX2MFT",
  "title": "Catherine",
  "gender": "Female",
  "aliases": ["Kathy"],
  "descriptors": ["tall", "blonde"],
  "race": null,
  "color": "#7C3AED",
  "notes": "",
  "firstAppearance": "chapter-3",
  "stats": { "totalLines": 142, "chapterCount": 9 },
  "voice": null,
  "provider": null,
  "voiceId": null,
  "voiceMeta": null,
  "manifestStats": null,
  "roleLabels": []
}
```

| Field | Type | Notes |
|---|---|---|
| `formatVersion` | `"3.0"` | Character version line (independent of the dialogue line). |
| `guid` | string | The identity. Normative spec below. Immutable for the cluster's life. |
| `title` | string | Display name. Filename derives from it. Changing it = file rename; the old title is appended to `aliases` (ruling R1). |
| `gender` | `Male \| Female \| Unknown` | As v2 (`types.ts:6`). |
| `aliases` | string[] | Surface forms. No "primary" — the title is the display name, full stop. |
| `descriptors` | string[] | Learned by `/api/review-chapter` and/or added in the UI. Removal is non-durable: a later review may re-append (documented, ruling R5). |
| `race`, `color`, `notes` | as v2 | Verbatim. |
| `firstAppearance` | string \| null | Derived; regenerated by the stats pass. |
| `stats` | `{ totalLines, chapterCount }` | Derived; regenerated from dialogue files. Never hand-edited. |
| `voice`, `provider`, `voiceId`, `voiceMeta`, `manifestStats` | as v2 | Verbatim. |
| `roleLabels` | string[] | **Must carry over from v2** — read by `dialogue_ai_context.py:288`, absent from the TS type, easy to lose. |
| `updatedAt` | ISO string | Set on every write. Used only for duplicate-GUID reconciliation (newest wins). |

Dropped from v2: `id` (name-derived slug — the name-coupling v3 exists to eliminate; every v2-id→GUID pairing is recorded in the migration backup/report). Legacy `count`/`chapterCount` top-level fields fold into `stats`.

## GUID spec (normative)

This section is the single source the migration, `character_store.py`, and the TS repository all implement against.

- **Length:** 8 characters (40 bits).
- **Alphabet:** Crockford base32, **uppercase**: `0-9` + `A-Z` minus `I, L, O, U` (32 symbols; no 0/O or 1/I/l confusables in an all-uppercase string).
- **Pattern:** `^[0-9A-HJKM-NP-QRSTV-Z]{8}$`
- **Generation:** exactly 5 random bytes → 40 bits → 8 base32 chars, big-endian. Frontend: `crypto.getRandomValues(new Uint8Array(5))`. Backend: `secrets.token_bytes(5)`. One shared encode table per language — same 40-bit space.
- **Migration minting (deterministic):** `SHA-256("<book-name>::v3::<v2-id>")` → first 5 bytes → 8 chars. A dry run reports exactly what `--apply` writes; a reset + re-migrate is reproducible.
- **Uniqueness:** mint-time check against the book's folder is mandatory (re-mint up to 5×, then raise). 40 bits → 50% collision at ~131k characters/book, ~3 orders beyond scale; the check makes it a non-issue. Concurrent-tab collisions are accepted and self-heal (memo: council-side rulings).
- **Stability:** immutable. A rename never touches the GUID. A merge keeps the *survivor's* GUID; the absorbed GUID dies with its file.
- **`narrator`:** reserved literal, non-GUID sentinel (already one everywhere: `fs.ts:379`, `closedWorldCharacterWorkflow.ts:162`, `jev_verify_service.py:96`). The narrator gets **no file**.
- **GUID→file resolution: a scan, not an index.** Readers read `characters/*.json` once per session/parse-run and build an in-memory `guid → {file, record}` map. **No `_index.json`** — an index is a second source of truth. Any cache is disposable.

## Filename rules

`characters/<sanitize(title)>.json`, where `sanitize`:

1. Replace `\/:*?"<>|` and control chars with `-`; collapse repeats; trim; cap 80 chars.
2. Guard Windows reserved names (`CON`, `NUL`, …) — prefix `-` if matched.
3. **Case-insensitive collision:** NTFS treats `Bob.json` / `bob.json` as one file. If two titles collide case-insensitively after sanitization, the colliding file is named by its GUID instead (`<GUID>.json`). The in-file `title` remains the true title. All lookups go by GUID from file **contents**, never by parsing filenames.
4. Title uniqueness (case-insensitive) is enforced at every write; a collision at runtime is rejected with a visible message (ruling R7).

The filename is a **cache of the title, not identity**.

## Reference formats in other files

Value type stays `string` everywhere; only the content changes (name/slug → 8-char uppercase GUID).

| File | Field | v3 value |
|---|---|---|
| `<Ch>/dialogue.json` | `lines[].characterId` | GUID; `null` stays = narrator |
| | `lines[].candidates[].characterId` | GUID |
| | `lines[].attribution.candidates[].characterId` | GUID or null |
| | `stats.characterBreakdown` | `{ guid: n }` |
| `<Ch>/<Ch>.characters.json` | `characters[]` | `[{ "id": "<GUID>" }]` — field name `id` unchanged, now carries the GUID; file `formatVersion` → `"3.0"` |
| `voices.json` | `assignments[].characterId` | GUID |
| | `voices[].metadata.usedByCharacters[]` | GUID (derived; regenerable) |
| `audio_lines/**/manifest.json` | top-level + per-clip `characterId` | GUID |
| | `characterName` (top-level + per-clip) | **unchanged — stays a name** (display/provenance) |
| `audio_lines/<Ch>/audio_lines/<Name>/` | directory name | **unchanged — name-based** (ruling R8; organizational, not identity) |

Unchanged deliberately: `attribution.candidates[].name`, `sourceAlias`, `sourceCandidates` — name-based provenance, part of the frozen wire contract.

Frozen wire contracts (byte-stable, now *sourced from the folder*): closed-world `characterCatalog` (`{characterId, name, aliases, descriptors, gender}`), `aliasToAdd`/`newCharacterProposal`, `descriptorsAdded`. The parser uses `characterId` only as an inert lookup surface (`booknlp_parser_service.py:82-85`), so GUIDs are transparent to `/api/parse`.

## Migration mapping (v2 → v3)

| v2 field | v3 disposition |
|---|---|
| `id` (slug) | retired; → minted `guid` (deterministic, recorded in backup + report) |
| `name` | → `title` |
| `gender`, `aliases`, `descriptors`, `race`, `color`, `notes`, `firstAppearance`, `stats`, voice fields, `roleLabels` | verbatim |
| legacy `count` / `chapterCount` | fold into `stats` (stats wins) |

Reference remap: old slug → new GUID at every site in the table above (exact string substitution; per-file atomic).

## Compatibility matrix

| Book state on disk | New app | Old app |
|---|---|---|
| `characters/` folder (≥1 valid v3.0 file), no `characters.json` | **v3 mode** — folder is SoT | **Hard "update required" gate** (ruling R10): dialogue/chapter reading works; character mutations blocked. Prevents silent `characters.json` resurrection. |
| `characters.json` v2.0, no folder | **auto-migrates on open** (ruling R9), then v3 mode | normal v2 |
| **Both present** | **Abort — migration-in-flight state.** Never silently picks a side; resume = re-open (idempotent) or restore from `_backups/character-v3/<ts>/` | (same gate as row 1) |
| Neither | derive-from-chapters fallback (fresh books); first cluster edit upserts a file with a minted GUID (silent auto-upsert, R7) | as today |

Writers: **v3 folder only.** Any writer that writes root `characters.json` when `characters/` exists is a bug (invariant IN-2, enforced in code).

**v1-script books** (ruling R11): character store migrates to the folder with GUIDs; v1 `script.json` files stay name-based (the format has no `characterId` slot). Documented intermediate state ("v3 store, v1 references") that resolves when a chapter is re-parsed.

## Validation rules

1. Every `characters/*.json` parses; `formatVersion === "3.0"`; `guid` matches the pattern; `title` non-empty.
2. GUIDs unique across the folder.
3. Titles unique case-insensitively (and after filename sanitization).
4. Every `characterId` in dialogue/rosters/voices/manifests resolves to a folder file (or is `null`/`narrator`).
5. Exactly one file per GUID.
6. Root `characters.json` absent (post-migration).
