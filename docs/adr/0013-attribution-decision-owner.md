# The attribution decision has one owning module

The per-line attribution decision record (ranked candidates plus `decisionTrace`) is owned by `py_services/openbook_parser/attribution_decision.py`, and this ADR records three commitments.

1. **One owner, one entry point.** Every writer (legacy sieve, parser ranking and its overrides, ModernBookNLP, the episode decoder, JEV verify) builds a `Decision` value and records it with `apply_decision(line, decision)`. Stage differences (ranked, promote an existing candidate, prepend a synthetic candidate, annotate the top row, keep) are carried in the decision data. Writers do not maintain trace invariants by hand. The owner keeps the chosen candidate first, `selectedCandidate` equal to the speaker, `selectedReasons` equal to the top candidate's reasons with override reasons appended, and `genderConflict` and `ruleCategory` recomputed. A verdict is additive and never rewrites the trace's decision fields (consistent with ADR-0006). Every emittable rule name is registered in exactly one of four categories: `HARD`, `CARRYOVER`, `LOCAL_EVIDENCE` or `FIRST_PERSON`. Consumer gate sets are derived from that registry, and a conformance test enforces exhaustiveness.
2. **The wire carries `ruleCategory`.** `decisionTrace.ruleCategory` is an additive camelCase field holding the category of the selected reasons (the strongest present wins: `FIRST_PERSON` > `HARD` > `LOCAL_EVIDENCE` > `CARRYOVER`). The frontend keeps no copy of the Python rule sets. Only traces written before the field existed fall back to a small TS first-person set.
3. **Assert/suggestion is one cross-language spec applied at each edge.** There is one set of thresholds (0.74 top, 0.14 margin, 0.80 unsupported top, 0.86 contested top) and one list of named suggestion rules, each scoped to the edge that applies it. The parser applies its edge in `rank_candidates`. The frontend (`attributionPolicy.ts`) applies its edge in `convertLineToDialogueLine` to the post-collapse candidate set, so it can un-assert a parser assert but never the reverse. Frontend-only checks (`no_named_candidates`, `speaker_blocked`, the first-person exemption) are named rules in the same spec. `tests/attribution_policy_vectors.json` pins both implementations and is run by the Python and TS suites.

**Considered options**: keep per-writer trace code with a shared invariant test only (the shape would still be re-stated in each writer, and wiring defects such as the dead `paragraph_sibling_speaker` signal stay invisible to any local interface). A single policy implemented on one side and consulted over the wire (rejected because the frontend judges a different, post-collapse candidate set). A frontend mirror of the Python rule-name sets (rejected because it is the hand-maintained cross-process parity this ADR removes). Some consumer gates are narrower than a whole category (JEV's carry-over targets and local-evidence shield, the ranking's support set), so the registry records them as per-rule gates in the same table rather than as extra categories.
