# Character stats are maintained incrementally from a stats accumulation

Character stats (per-character `totalLines` and `chapterCount`) are no longer recomputed by a full book rescan on every dialogue save. The backend keeps an in-memory **stats accumulation** — per-character, per-chapter line counts — built when the book root is set and lazily rebuilt after a restart. A dialogue save applies only the saved chapter's delta to the accumulation and writes the changed character files, in the background and off the event loop. Stats are therefore eventually consistent: a crash between the dialogue write and the delta apply, or a save that bypasses the delta, leaves stats stale until a full rebuild. The manual "update stats" action (full rescan) is the documented repair, and the v3 migration performs an explicit full rebuild.

**Considered options**: full rescan per save (status quo — O(book) I/O and a blocked event loop on every assignment); debounce/batch the rescan per burst (still O(book) per burst, and the substring trigger on `/api/save` would remain); persisted per-chapter counts in chapter data (a schema change for no extra benefit over the in-memory matrix); frontend-held matrix (dual-I/O modes could diverge, and FSA mode has no backend write to hook).
