# The pipeline progress record describes itself, and the FE only polls it

A chunked character run happens inside one synchronous request, so the UI learns what it is doing only by polling a `progress.json` the pipeline writes at each phase boundary. One module owns that file: `py_services/audio/pipeline_progress.py`. It decides where the record lives (`resolve_run_location`: one distinct line chapter means `single` scope under `<chapter>/audio_lines/<character>`, more than one means `cross` under `_book_batch/<character>`), what it says (`phase` from the `Phase` enum, `scope`, `detail`, `lineCount`, `chunkIndex`/`chunkTotal`, `startedAt`, `updatedAt`) and how it is written (atomic tmp+replace, never raises). The pipeline, its failure path and `GET /api/vibevoice/character/progress` all go through it.

Three rules are binding:

1. **The BE is the only side that derives location and scope.** The run binds a `ProgressTracker` once. The failure path writes `failed` through that tracker and does not re-derive the location from the request. The route takes the character and the chapter that was asked for, checks both locations with `read_progress`, and returns the newest record with its `scope`. The FE sends no `cross_chapter` and does not compute it.
2. **The FE is a dumb poller.** `audioPipelineProgress.ts` turns the response into one `PipelineProgressRecord` and hands it to `onProgress`. The display reads it directly: the phase label shows true engine-chunk progress ("chunk 3 of 7", the counts ADR 0018 makes true), and nothing turns chunks back into a pseudo line count.
3. **A run's record starts at `starting`.** That write opens a fresh record, and later writes keep its `startedAt` and carry `lineCount`/`chunk*` forward. The poller drops records whose `startedAt` is more than 5 s older than its request.

Phase names, scopes and record keys are pinned for both languages by `tests/pipeline_progress_vectors.json` (py: `test_pipeline_progress.py`; TS: `__tests__/pipelineProgress.test.ts`), the same pattern as ADR 0015.

**Considered options**: keep the FE computing `crossChapter` (the two derivations must agree or the poll reads the wrong file, and no test pinned that); an in-memory run registry so the route needs only the character (lost on restart, and the probe already settles it); keep the panel's chunk-to-line rescale (it is invented precision). Accepted costs: during speech generation the queue overlay's line and character counters no longer move. Only the phase label does, until the queue job gets a real progress field (candidate 8). If one character has runs in both locations, the newer one wins. Fixed on the way: a repeat run in the same work dir used to inherit the previous run's `startedAt`, so the poller dropped all of its progress.
